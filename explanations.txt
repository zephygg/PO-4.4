leetcode 88-96 explanations
===========================


88. merge sorted array
----------------------
goal: merge nums2 into nums1 in place, both already sorted. nums1 has empty
space at the end.

idea: if we merge from the front we'd overwrite nums1's own values. so go
from the back instead. use three pointers: i (last real element of nums1),
j (last of nums2), k (last slot of nums1). at each step put the bigger of
nums1[i] and nums2[j] into slot k and move that pointer left.

we only need to loop until nums2 is used up, because whatever is left of
nums1 is already in the right place.

time O(m+n), space O(1)


89. gray code
-------------
goal: sequence of 2^n numbers where neighbors differ by exactly one bit.

idea: there's a closed formula. the i-th gray code is i ^ (i >> 1). shifting
i right by one and xoring with itself means that going from i to i+1 only
flips one bit of the result.

example n=2: i=0..3 -> 00, 01, 11, 10

time O(2^n), space O(1) besides the output


90. subsets II
--------------
goal: all subsets of a list that may contain duplicates, with no repeated
subsets.

idea: sort first so duplicates sit next to each other. then backtrack: at
each level, loop over the choices from `start` onward. if nums[i] equals
nums[i-1] and i > start, skip it. that means "i already tried this value at
this position in the recursion", so picking it again would make a duplicate
subset.

every node of the recursion tree is a valid subset, so we add the current
path to the result at the start of each call.

time O(n * 2^n), space O(n) for recursion


91. decode ways
---------------
goal: count how many ways a digit string can be decoded as letters
(1->A ... 26->Z).

idea: dp. let ways(i) be the number of ways to decode the first i chars.
- if the current digit isn't '0', it can stand alone: add ways(i-1)
- if the last two digits form a number from 10 to 26, they can be one
  letter: add ways(i-2)

a '0' can't stand alone, so a string starting with '0' gives 0, and a lone
'0' that doesn't pair up with a valid number gives 0 for that step.

only the last two values matter, so we keep two variables instead of an
array.

time O(n), space O(1)


92. reverse linked list II
--------------------------
goal: reverse the nodes from position left to right, in one pass.

idea: use a dummy node before head so that left=1 isn't a special case.
walk `pre` to the node just before position left. then `cur` is the first
node of the section. repeat (right - left) times:
  - take the node after cur (nxt)
  - cut it out (cur.next = nxt.next)
  - insert it right after pre (head insertion)

cur stays put and keeps drifting toward the end of the section while each
new node gets pushed to the front, which reverses the section.

time O(n), space O(1)


93. restore ip addresses
------------------------
goal: all valid ways to split a digit string into 4 parts of a valid ip.

idea: backtracking. try to take 1, 2 or 3 digits for the next part. a part
is valid if it is at most 255 and has no leading zero (except "0" itself).
stop when we have 4 parts: if we've used the whole string it's a valid
answer, otherwise throw it away.

the search is tiny because there are at most 3 choices for 4 levels, so
81 paths total.

time O(1) in practice (bounded by 3^4), space O(1)


94. binary tree inorder traversal
---------------------------------
goal: return values in left, root, right order.

idea: the recursive version is 3 lines, but the iterative one with a stack
is the usual follow-up. go as far left as possible while pushing nodes on
the stack. when you can't go left anymore, pop a node, record its value,
then move to its right child and repeat.

the stack basically holds "ancestors we still need to visit after finishing
their left subtree".

time O(n), space O(h) where h is the tree height


95. unique binary search trees II
---------------------------------
goal: build every structurally unique bst that stores values 1..n.

idea: recursion over ranges. build(lo, hi) returns all trees using values
lo..hi. pick each value as the root. every value smaller than it goes to the
left subtree (build(lo, root-1)) and every bigger one goes right
(build(root+1, hi)). combine every left option with every right option.

an empty range returns [None], so the loops still run once and attach a
null child.

the number of trees is the catalan number, so it grows fast. time and space
are both about O(4^n / sqrt(n)).


96. unique binary search trees
------------------------------
goal: just count the trees from problem 95, not build them.

idea: same split as 95. with `nodes` values, pick a root, which leaves
(root-1) values for the left and (nodes-root) for the right. the number of
trees for that root is left_count * right_count. add up over all roots.

dp[0] = dp[1] = 1, then
dp[nodes] = sum of dp[root-1] * dp[nodes-root] for root in 1..nodes

this is the catalan number sequence, so you could also use the closed form
C(2n, n) / (n+1).

time O(n^2), space O(n)
